第一章 · 产品定位

什么是 TraeWork

入门 一句话理解：把工作目标交给 AI 推进

TraeWork 是一款 AI 原生工作台。它提供网页端、桌面端和移动端三种形态，并围绕不同用户和任务场景提供 Work、Code、Design 三个模式。

一句话理解：TraeWork 可以把你的工作目标交给 AI 来推进。你只需要说明想完成什么，AI 会帮你拆解步骤、执行任务、生成结果，并根据你的反馈继续修改。

1.1 三端形态

形态适合场景你可以怎么用
桌面端长期任务、复杂项目、本地文件或代码任务支持文字、语音、附件、技能等输入，可在对话中查看进度、预览产物和验收结果
移动端碎片化场景下发任务、查看进度、补充要求在手机上发起任务、管理云端和已连接电脑中的任务，并与其他端同步
网页端临时需求、快速验证、外出办公打开网页即可使用云端环境，无需下载安装（中国版 work.trae.cn / 国际版 work.trae.ai）

1.2 它能帮你做什么

把目标变成产物

从"我想做什么"出发，推进到文档、代码、报告、原型、网页等可交付结果

把复杂步骤交给 AI

AI 负责拆解步骤、读取上下文、调用工具、执行任务，你负责确认方向和验收

把经验沉淀下来

通过 Skill、规则、记忆、MCP 等能力，把一次性经验变成持续复用的资产

让任务跨端接续

同一个任务可在网页、桌面、移动端之间同步查看和继续推进

第二章 · 核心差异

TraeWork vs 普通 Chatbot

入门 Chatbot 回答你，TraeWork 和你一起把任务完成

很多人第一次接触 TraeWork，会以为它只是一个"更强的 AI 聊天框"。但它的价值远不止于此——和普通 Chatbot 不同，TraeWork 能接住任务、理解上下文、调用工具、产出文件，并在本地、云端和移动端之间持续推进工作。

对比维度普通 ChatbotTraeWork
核心交互以问答为主，回答建议或生成文本以任务为中心，目标是把任务执行到可验收产物
任务推进需要用户手动拆解和复制粘贴上下文Agent 理解目标、拆解步骤、读写文件、调用工具并持续推进
上下文能力更多依赖当次对话输入支持项目上下文、全局记忆、文件、技能、MCP 等多种来源
过程控制过程不可见，主要看到最终回复执行过程透明，可查看进度、补充要求、纠偏和验收
交付形式常见输出是文本答案输出文档、PPT、图表、网页、代码变更、设计稿等多种产物
能力扩展主要依赖模型本身通过 Skill、MCP、记忆、规则等扩展能力边界

Chatbot 更擅长"回答你"；TraeWork 更强调"和你一起把任务完成"。

第三章 · 三种模式

Work / Code / Design

入门 写材料用 Work，看代码用 Code，做界面用 Design

TraeWork 顶部提供三种模式，分别对应办公协作、开发执行和设计创作场景，覆盖不同人群。狭义上一句话理解：Work 负责把事情想清楚，Design 负责把产品画出来，Code 负责把它真正做出来。

模式适合人群典型任务
Work产品经理、运营、数据分析师、市场、学生、职能等多角色人群处理文档、数据、PPT、研究分析、内容生成、工作总结、生成并分享 HTML 页面
Code习惯让 AI 主导开发的工程师和技术用户编码、调试、理解代码库、处理 Git 工作流、修复 Bug、测试
Design设计师、产品、前端、需要快速做视觉方案或原型的用户生成设计稿、导入 Design Library、风格探索、预览编辑设计、导出到 Code 模式

4.1 Work 模式场景举例

我上传了一批用户反馈，请帮我按功能问题、体验问题、内容建议、付费相关等类别整理，并提炼出一份需求清单。每条需求请包含：用户原话摘要、核心问题、影响范围、优先级建议。
请根据我上传的表格数据，生成一份运营日报。重点分析今日核心数据表现、环比变化、异常波动原因，并给出 3 条可执行的运营建议。语言简洁，适合发给团队同步。

4.2 Code 模式场景举例

登录时出现【具体问题/报错信息】，请帮我定位原因并修复。你可以先阅读相关代码，找到可能出问题的文件和逻辑，再给出修改方案并完成代码改动。修复后请说明问题原因、改了哪里，以及建议我如何验证。
请帮我阅读这个项目的代码结构，梳理主要目录和关键模块的作用。重点说明项目入口、核心业务逻辑、数据流转方式、配置文件和测试位置。请用新同学也能看懂的方式解释。

4.3 Design 模式场景举例

我想从 0 设计一个【产品/页面类型】。目标用户是【用户群体】，核心场景是【使用场景】。请先帮我探索 3 个不同的视觉方向，包括整体气质、配色、字体、布局风格和适合的组件形式。每个方向请说明适合什么场景，并给出可视化初稿。
三句口诀选模式

写材料、做分析，用 Work；看代码、改项目，用 Code；做界面、出设计，用 Design。三个模式也可以灵活搭配——例如把 Design 模式生成的设计图直接导入 Code 模式，无缝衔接开发。

第五章 · 执行环境

云端任务 vs 本地任务

入门 选对环境，任务跑得更顺
环境含义适合场景
云端任务在远程环境中执行，不占用本机资源调研、写文档、生成内容、跨设备继续处理
本地任务在你的电脑本地执行需要访问本地文件、本地项目或本机环境的任务
选择建议

只是写文档、做调研、整理内容，优先使用云端；任务需要读取或修改你电脑上的文件、项目，再考虑本地。

第七章 · 入门技巧

8 个 TraeWork 入门技巧

入门 从"更聪明的聊天框"到"持续协作的工作伙伴"

用好 TraeWork 的关键，不只是收藏更多提示词，更多的是建立一套稳定的协作方式：如何发起任务、如何补充上下文、AI 执行过程中如何提前干预、重复工作如何释放人力。

1选择适合的产品模式

不要把所有任务都塞在一个模式里。Work 关注业务目标和交付物，Code 关注仓库、依赖和代码质量，Design 关注布局、样式和体验细节。三个模式可灵活搭配——例如 Design 生成的设计图可直接导入 Code 无缝衔接开发。

2创建项目文件夹，补充上下文

把与任务相关的资料统一放在一个文件夹中，在 TraeWork 里选择该文件夹再下达指令。比起不选文件夹，AI 找数据、放结果的效率和稳定性都会高很多。

帮我分析这个文件夹里的评论，并整理成 Excel。

3开发不着急，先用 Spec / Plan 规划

Code 模式下，在对话框输入 / 可调用两个规划命令：

  • Plan 模式：适用于中小型功能开发和模块级重构，生成计划文档后直接执行
  • Spec 模式：面向更复杂的系统级任务，生成完整的三阶段文档组（大纲 + 任务列表 + 验收清单），每阶段支持确认和 Refine
/spec 开发一款支持多语种学习的在线教育平台，涵盖英语、日语、韩语等主流语言……

4语音功能，帮你理清思绪

第二十七章 · 公众号推文

「我的文件」正式上线：一个空间装下所有工作产物

最新 TraeWork 从「工具」升级为你的「工作入口」

本文整理自 TRAE 微信公众号推文（mp.weixin.qq.com/s/N2dMLK6YQnSfEoAjYX1ouQ）。

做完的东西，下次还想改，你通常会经历什么？在飞书里翻、在对话记录里翻、在本地文件夹里翻——找文件，比改文件还慢。产物一旦做完，就散落在任务、对话和各类文件夹里，下次想接着改，得先花时间把它扒出来，再把上次的背景重新交代一遍。

今天，TraeWork「我的文件」正式上线。它把你在 TraeWork 里做出的 HTML 产物、图片、视频产物，全部汇聚到一个空间——找到就能改，打开即续写，上下文自动关联，离交付更近一步。

28.1 一个空间，装下你所有的工作产物

过去，产物存在一个个 Task 里，你得先想起"那次对话叫什么"，才能找回它。现在进入「我的文件」，所有产物一目了然，按来源分成三类：

本地产物

本机创建和编辑的产物，随手可取

云端产物

保存到云端的产物，Desktop 和 Web 两端同步访问，换设备也不丢

飞书产物

同步到飞书的产物，团队一起看、一起改，协作不断线

不管是 HTML 页面、图片还是视频，都在同一个页面陈列。你不再需要记住它存在哪，只需要打开「我的文件」。

28.2 两种视图，怎么找都顺手

同一份产物，TraeWork 准备了两种"找回它"的方式：

  • 网格缩略图：只记得大概长什么样？缩略图铺开，看一眼封面就认出来
  • 列表视图：清楚知道要找哪份？名称、修改时间、来源一列排开，一下锁定

支持置顶、搜索和分组，下次再找不用翻。

28.3 打开即续写，上下文不用重讲

这不只是一个"文件夹"。每个产物都可以关联到对应的 Task。打开文件，可以查看完整对话和生成过程，无缝衔接上一次的工作——不用重新解释这是什么报告，也不用从头描述需求。

除了回到原 Task，你还可以：

  • 置顶产物，把高频文件固定在最前
  • 打开对应任务，回到它诞生的那次对话
  • 带着产物新建对话，换一个思路继续做
  • 分享 / 打开本地文件夹 / 删除，常用文件操作集中完成

28.4 越反复改，越离不开

「我的文件」为高频迭代的知识工作者而生：产品经理持续更新竞品分析，运营每周维护活动页面，数据分析师定期更新看板——这些工作都不是"从零生成"，而是围绕已有成果持续迭代。

使用方式

将 TraeWork 更新至最新版本，进入「我的文件」，让你的每一份产物，都能一秒找回、打开即续。

常见问题 FAQ

TraeWork 是不是只能给开发用？

不是。Code 模式面向开发任务，但 Work 模式更适合文档、数据、汇报、分析等通用办公场景；Design 模式面向设计和原型场景。

会用普通 AI 聊天工具，还需要 TraeWork 吗？

如果只是问知识、写短文本，普通聊天工具够用。如果希望 AI 读取资料、拆解任务、调用工具、生成可交付产物，并能跨端持续推进，TraeWork 更合适。

应该用网页版还是桌面端？

临时任务、快速体验、云端任务可先用网页版；长期项目、本地文件、代码仓库和复杂任务更建议桌面端。

云端模式和本地模式选哪个？

只是聊天、查资料、写文档、生成内容优先选云端；需要 AI 读取或操作电脑上的文件、项目，选本地。

Design 模式是不是 Figma 的替代品？

不是简单替代。Design 模式更像 AI 设计协作入口，可导入设计资产、生成方案、二次编辑，并和 Code 模式衔接，帮助设计从创意走向实现。

中国版和国际版注册有什么差异？

中国版支持手机号、抖音、苹果账号；国际版支持邮箱和第三方账号授权（如 Google、GitHub）。实际可用方式以登录页展示为准。

任务列表里的任务可以切换吗？

可以。点击左侧任务列表中的任务，就能回到对应任务的对话和执行记录。

为什么有时候右侧栏是空的？

如果任务还没开始执行，或当前任务没有生成待办、产物和参考信息，右侧栏可能为空。复杂任务执行后通常会出现进度和产物。

技能是什么？怎么用？

技能就像给 AI 安装的能力包，让 AI 在特定任务中表现更稳定。点击左侧栏的"技能"，可进入技能市场安装或管理技能。

AI 误删了文件怎么办？

TraeWork 安全沙箱机制将删除文件加入电脑的回收站，AI 操作中被误删的内容可直接从回收站找回。
